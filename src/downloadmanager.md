# OHIF Download Manager Extension Architecture

> **Author**: **Nick Hermans** (Medical Imaging Engineer, UZ Leuven — Information Technology and Data Department, PACS, eHealth HUB and Telematics team) — [`nick.hermans@uzleuven.be`](mailto:nick.hermans@uzleuven.be)  
> **Package**: `@ohif/extension-download-manager` (OHIF Viewer v3 Platform)

The Download Manager extension enables clinicians, researchers, and PACS administrators to filter, batch export, package, and anonymize medical imaging datasets directly from the OHIF Viewer. It generates a non-identifying directory hierarchy, validates UIDs, and normalizes metadata for DICOM compliance.

## Architecture

The extension executes **100% client-side** in the browser, interacting with the PACS/DICOMweb backend using the active session security context and authorization tokens managed by OHIF's `UserAuthenticationService`.

### Core Modules
* **`index.tsx`**: Extension entry point registering OHIF commands (`openDownloadManager`), modes, and panels.
* **`anonymizer.js`**: Core DICOM PS 3.15 Annex E header anonymizer engine handling tag rules and de-identification provenance injection (`0012,0062`, `0012,0063`, `0012,0064`, `0018,A001`).
* **`anonymizer-config.js`**: Persistent anonymizer settings, rules, and default configuration.
* **`anonymizer-rules.js`**: Data Element dictionary mapping DICOM tags to action keywords (`KEEP`, `REMOVE`, `CLEAN`, `REPLACE`, `HASH`).
* **`pixel-redactor.js`**: Image pixel redaction engine handling sequential multi-frame scanning and fail-closed safety constraints.
* **`ocr-engine.js`**: Micro-OCR character recognition engine & Stroke-Width Transform (SWT) contour topology analyzer.
* **`phi-classifier.js`**: RSNA PHI vs clinical measurement overlay classifier.
* **`dicom-codecs.js`**: WebAssembly DICOM codec pipeline supporting encapsulated syntaxes (JPEG 2000, JPEG-LS, HTJ2K, RLE Lossless, JPEG Lossless/Baseline).
* **`downloader.js`**: Queue manager handling fetch streams, HTTP retries, manifest generation, and delegating to storage writers.
* **`manifest.js`**: Compiles dataset selection trees, pre-flights SOP Instance UIDs, and formats non-identifying path hierarchies.
* **`writers/zipWriter.js`**: High-performance streaming ZIP writer utilizing OPFS (Origin Private File System) and IndexedDB chunk buffers to eliminate browser memory OOM errors.
* **`writers/folderWriter.js`**: Native File System Access API writer for Chrome/Edge direct folder streaming.
* **`utils.js`**: Utility functions for UID validation, text sanitization, and path collapsing.

## Directory Layout Specification

Exports generated by the Download Manager follow a non-identifying, neutral directory structure to prevent PHI disclosure in filesystem paths:

```text
dataset/
├── export-manifest.json
├── checksums.sha256
└── Patient_<StudyUID_suffix>/
    └── Study_<StudyUID_suffix>/
        └── Series_<SeriesNumber>_<SeriesUID_suffix>/
            ├── <SOPInstanceUID>.dcm
            └── ...
```

### Components
1. **Patient Directory**: Derived from the StudyInstanceUID suffix (e.g. `Patient_12345678`), avoiding Patient Name or Patient ID in directory names.
2. **Study Directory**: Derived from the StudyInstanceUID suffix (e.g. `Study_12345678`).
3. **Series Directory**: Combination of series number and series UID suffix (e.g. `Series_001_87654321`).
4. **Filename**: Retains `<SOPInstanceUID>.dcm` (or `.mp4` for video instances).
5. **Manifest & Checksums**: Root files `export-manifest.json` and `checksums.sha256` provide complete dataset records and SHA-256 cryptographic verification hashes.

### Filesystem Sanitization Rules
Directory strings are sanitized for Windows, macOS, and Linux compatibility:
1. Invalid filesystem characters (`< > : " / \ | ? *`), control characters, tabs, and nulls are replaced with an underscore `_`.
2. Whitespace runs and `^` (caret) characters are compressed to `_`.
3. Repeated runs of underscores are collapsed to a single `_`.
4. Trailing periods and spaces are trimmed.
5. `SeriesNumber` is preserved as a three-digit zero-padded string (e.g., `1` → `001`).
6. Segment lengths are capped at 120 characters to prevent path-too-long errors on Windows. Duplicate directory collisions receive a deterministic `_DUP02`, `_DUP03` suffix.
